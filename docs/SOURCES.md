# Verified primary sources

All execution uses the consistent LEZ → SDK → Blockchain pins below.

- [RFP-022, pinned](https://github.com/logos-co/rfp/blob/920fad928a4592f0fdf4356046a06973fb5c931d/RFPs/RFP-022-wrapped-erc20.md): strict trust model, permissionless infrastructure, private burn/release pairing. Snapshot retained under `evidence/source/`.
- [LEZ manifest](https://github.com/logos-blockchain/logos-execution-zone/blob/14cb5d092e70c3d1fc014d4921d0b13bea197b5d/Cargo.toml), [SDK manifest](https://github.com/logos-blockchain/logos-zone-sdk/blob/1b5073a10caaa63cbbd825bd4397f2f1fb48b33a/Cargo.toml): consistent native dependency pins.
- [LEZ block commitments](https://github.com/logos-blockchain/logos-execution-zone/blob/14cb5d092e70c3d1fc014d4921d0b13bea197b5d/lez/common/src/block.rs): receipts ARE hash-bound; `BedrockStatus` is not. Both are checked in the harness.
- [LEZ block acceptance](https://github.com/logos-blockchain/logos-execution-zone/blob/14cb5d092e70c3d1fc014d4921d0b13bea197b5d/lez/chain_state/src/apply.rs): native receipt derivation and mismatch rejection; reused directly.
- [Final tier](https://github.com/logos-blockchain/logos-execution-zone/blob/14cb5d092e70c3d1fc014d4921d0b13bea197b5d/lez/chain_state/src/chain.rs): `apply_final_block` can park invalid finalized inscriptions.
- [Private validation](https://github.com/logos-blockchain/logos-execution-zone/blob/14cb5d092e70c3d1fc014d4921d0b13bea197b5d/lee/state_machine/src/validated_state_diff/mod.rs): proof, commitment freshness, nullifiers and public settlement are separate checks. [State serialization/root history](https://github.com/logos-blockchain/logos-execution-zone/blob/14cb5d092e70c3d1fc014d4921d0b13bea197b5d/lee/state_machine/src/state/mod.rs): a private commitment root alone is not the complete state. `genesis_fingerprint` exists, but neither it nor the prototype's full-state digest is a consensus-enforced header root.
- [Publisher](https://github.com/logos-blockchain/logos-execution-zone/blob/14cb5d092e70c3d1fc014d4921d0b13bea197b5d/lez/sequencer/actors/bedrock/src/actor/publisher.rs): block to channel inscription; the harness supplies actual accepted block bytes to native authentication.
- [Indexer LIB RPC](https://github.com/logos-blockchain/logos-execution-zone/blob/14cb5d092e70c3d1fc014d4921d0b13bea197b5d/lez/chain_state/src/zone_indexer.rs): RPC `lib_slot` bounds a node's read, not an Ethereum-verifiable proof.
- [Native inscription verifier](https://github.com/logos-blockchain/logos-blockchain/blob/a159f8c155df68d7e2f045a418ae737de246354e/core/src/mantle/ops/channel/inscribe.rs), [body root](https://github.com/logos-blockchain/logos-blockchain/blob/a159f8c155df68d7e2f045a418ae737de246354e/core/src/block/mod.rs), [header](https://github.com/logos-blockchain/logos-blockchain/blob/a159f8c155df68d7e2f045a418ae737de246354e/core/src/header/mod.rs): reused native authentication and body hashing. Header and inscription definitions have an empty diff against the specified newer Blockchain HEAD.
- [Leadership public inputs](https://github.com/logos-blockchain/logos-blockchain/blob/a159f8c155df68d7e2f045a418ae737de246354e/ledger/src/cryptarchia/mod.rs): `try_apply_proof` derives aged/latest UTXO roots and epoch/lottery inputs from ledger state. [Consensus engine](https://github.com/logos-blockchain/logos-blockchain/blob/a159f8c155df68d7e2f045a418ae737de246354e/consensus/cryptarchia-engine/src/lib.rs) distinguishes bootstrapping and online LIB/fork choice.
- [Cryptarchia protocol](https://github.com/logos-co/logos-lips/blob/8784398f0fc9402ab1daac187dcb897881d427f7/docs/blockchain/raw/cryptarchia-v1-protocol.md), [bootstrap](https://github.com/logos-co/logos-lips/blob/8784398f0fc9402ab1daac187dcb897881d427f7/docs/blockchain/raw/cryptarchia-v1-bootstr-sync.md), [fork choice](https://github.com/logos-co/logos-lips/blob/8784398f0fc9402ab1daac187dcb897881d427f7/docs/blockchain/raw/fork-choice.md), [PoL](https://github.com/logos-co/logos-lips/blob/8784398f0fc9402ab1daac187dcb897881d427f7/docs/blockchain/raw/cryptarchia-proof-of-leadership.md): replay, peer/network assumptions, prolonged bootstrap and trusted-checkpoint distinction. Headers alone do not provide executed ledger state.
- [SDK bridging](https://github.com/logos-blockchain/logos-zone-sdk/blob/1b5073a10caaa63cbbd825bd4397f2f1fb48b33a/zone-sdk/BRIDGING.md): accredited-key threshold withdrawals are not a trustless Ethereum verifier.
- [Cross-zone witness](https://github.com/logos-blockchain/logos-execution-zone/blob/14cb5d092e70c3d1fc014d4921d0b13bea197b5d/lez/programs/cross_zone_inbox/core/src/lib.rs): `l1_inclusion_witness` MUST be None in v1. [Native bridge Withdraw](https://github.com/logos-blockchain/logos-execution-zone/blob/14cb5d092e70c3d1fc014d4921d0b13bea197b5d/lez/programs/bridge/src/main.rs) is disabled; the independent burn guest demonstrates this does not prohibit writing custom programs.
- [Native Zone roadmap v5](https://github.com/logos-co/roadmap/blob/v5/content/blockchain/roadmap/native_zone.md): STF enforcement specification/implementation boxes remain incomplete; downloaded bytes retained because the branch name is mutable.
- [RISC Zero release 3.1.0](https://github.com/risc0/risc0/releases/tag/v3.1.0), [zkVM advisory](https://github.com/risc0/risc0/security/advisories/GHSA-g6qg-9j8p-7j87), [Ethereum advisory](https://github.com/risc0/risc0-ethereum/security/advisories/GHSA-mm6c-35cm-g4x2), [Ethereum verifier source](https://github.com/risc0/risc0-ethereum/blob/ff30da77ba4afdd496290ebebedb205348b15d83/contracts/src/groth16/RiscZeroGroth16Verifier.sol). Verification uses real receipts with `RISC0_DEV_MODE=0`. The local EVM verifies the redemption statement as a Groth16 proof. The historical restricted checkpoint receipt is Composite.
